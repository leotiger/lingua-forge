7/**
8 * Encrypted storage for AI provider API keys.
9 *
10 * Envelope versions (cohabitating, see read-path dispatcher):
11 *
12 *   v2 — AES-256-GCM, authenticated, with provider slug as AAD.
13 *        Storage: "v2|" + base64( IV(12) || ciphertext || tag(16) )
14 *        Default for every write since 2026-05-20 (§3.5). The AAD
15 *        binds the ciphertext to the wp_options row that holds it —
16 *        an attacker with DB write access can no longer swap an
17 *        Anthropic blob into the OpenAI slot (the GCM tag check fails).
18 *
19 *   v1 — AES-256-CBC, no MAC. Storage: base64( IV(16) || ciphertext ).
20 *        Legacy. Kept readable indefinitely so the plugin survives
21 *        DB restores from pre-upgrade backups. Any successful v1 read
22 *        is opportunistically re-encrypted as v2 in-place (lazy
23 *        migration). New writes never produce v1 again.
24 *
25 * The encryption secret is derived from WordPress's own auth salts
26 * (wp-config.php), so the plaintext key is never stored in the database.
27 *
28 * Fallback resolution order for get():
29 *   1. Encrypted value in wp_options  (set via the Settings page)
30 *   2. Server environment variable    (e.g. ANTHROPIC_API_KEY)
31 *   3. PHP constant                   (e.g. define('ANTHROPIC_API_KEY', '…'))
32 *
33 * This means existing setups using env vars or wp-config.php constants
34 * continue to work without any changes.
35 *
36 * Optionally define LINGUAFORGE_SECRET in wp-config.php to use your own
37 * encryption secret instead of the derived wp_salt value.
