3 * Class LinguaForge\AI\Features\TranslationBackfill
4 *
5 * Self-heals posts left with missing-language gaps after a queued translation
6 * (TranslationQueue::run_queued()) times out, errors, or is otherwise lost —
7 * e.g. a cron tick that never fired, an Action Scheduler action that expired,
8 * a provider outage mid-request. Without this, such a gap is silent: nothing
9 * ever revisits it, and an admin only discovers it by noticing a missing
10 * language switcher entry, or by running the `missing_translations` /
11 * `fill_translations` WP-CLI commands by hand.
12 *
13 * A recurring cron tick (self::run(), hooked to self::CRON_HOOK) periodically
14 * re-derives the same "which posts are missing which active language" gap
15 * those CLI commands compute, and re-queues just the missing (post, lang)
16 * pairs via TranslationQueue::queue() — the same async pipeline a normal save
17 * uses, so a recovered translation goes through the identical create/update +
18 * TRID-link + cache-clear flow.
19 *
20 * Per-(post, lang) failure state (attempt count, last-attempt time, last
21 * error) is written by TranslationQueue::run_queued() on every queued job —
22 * success or failure — via record_failure() / clear_failure() below. This
23 * scan reads that state to avoid hammering a (post, lang) pair that keeps
24 * failing for a structural reason (e.g. a revoked API key) on every single
25 * cron tick: once a pair has failed MAX_ATTEMPTS times in a row, it's left
26 * alone for COOLDOWN_SECONDS before the next attempt — enough for a bad key
27 * to get fixed or a provider outage to end without an unbounded retry storm.
28 *
29 * @since 2.5.3
30 */
31
